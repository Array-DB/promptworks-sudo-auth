# v3.4.1 bootstrap handoff fix

v3.4.1 hardens the one-time ADB provisioning handoff.

- The Android activity persists `pw_url` and `pw_token` synchronously before Compose renders.
- `onNewIntent()` also imports bootstrap data if Android reuses an existing launcher activity after an APK update.
- The installer launches with `am start -S -W` and requires a non-secret log acknowledgement that both values arrived.
- The enrollment token itself is never written to logcat and is still removed by the app after successful enrollment.
- If ADB delivery fails, the installer stops before PAM installation instead of claiming the field was prefilled.
