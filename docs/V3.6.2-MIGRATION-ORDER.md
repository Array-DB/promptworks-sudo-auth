# v3.6.3 Protected Migration Ordering

The current PromptWorks pair remains authoritative until the replacement APK is installed, provisioned, and a fresh old-PAM authorization succeeds.

## Required state machine

```text
OLD APK + OLD PAM = ACTIVE
        |
        | unprivileged Android build/install
        v
OLD APK + OLD PAM = ACTIVE     NEW APK = INSTALLED, UNTRUSTED
        |
        | OLD PAM authorizes privileged provisioning setup
        v
OLD APK + OLD PAM = ACTIVE     NEW APK = CANDIDATE, SEALED
        |
        | sudo -K, then fresh OLD PAM authorization
        v
NEW APK + NEW PAM = ACTIVE     OLD APK = NOT TRUSTED
```

The trust switch never occurs merely because the replacement APK was installed. The installer invalidates cached sudo credentials immediately before the protected exchange so the currently-installed PAM stack and its currently-enrolled old APK must participate.

The new APK uses `com.promptworks.sudoauth.secure`, so it can coexist with the earlier `com.promptworks.sudoauth` package.
