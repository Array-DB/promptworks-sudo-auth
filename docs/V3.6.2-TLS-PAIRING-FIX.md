# v3.6.3 provisioning TLS ordering fix

v3.6.1 could build the side-by-side APK before the temporary provisioning CA existed. The APK could therefore contain a stale CA while the server later used a newly generated CA, causing Android/Java `CertPathValidatorException: Trust anchor for certification path not found`.

v3.6.3 generates a fresh per-installation CA and IP-bound server certificate **before** Gradle builds the new APK, embeds that exact CA into `res/raw/promptworks_server_ca.pem`, then later installs the exact same staged certificate material for the temporary HTTPS server. The installer verifies CA fingerprints before starting the server and refuses to continue on mismatch.

The TLS staging private keys are mode 0700/0600-equivalent user-private build material and are removed after successful provisioning server retirement. The existing/old PAM and APK remain the trust anchor for privileged migration steps until the final switch.
